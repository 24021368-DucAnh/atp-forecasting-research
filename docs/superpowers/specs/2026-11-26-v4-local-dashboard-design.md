Owner selected local Streamlit + SQLite and explicitly requested implementation after review. Accepted V3 checkpoint: 410ec717a69c58e5724a93e364158219c1447f1e. V3 source, historical evidence and permission registry are immutable within V4 scope. New private noncommercial research only; no wagering, allocation, commercial, public hosting or independent validation claim. Default real data, network ingestion, fitting and model export locked. No automatic future holdout reservation.

## Product and architecture
Windows single-user local web app, loopback 127.0.0.1:8501. Streamlit reads a view model; separate worker owns database writes. SQLite WAL, foreign keys, explicit transactions, bounded busy timeout, migration versions, backup/restore and single-worker OS/job lease with recovery. Task Scheduler optional, disabled initially; no live work while PC is off. No API calls or training in Streamlit rerun. No external assets/telemetry by default. Secrets via local environment, never tracked or logged. Local data, models and logs ignored. No untrusted pickle/model load.
Alternatives considered: local Streamlit/SQLite (selected), cloud PostgreSQL (deferred), full-stack (unnecessary for MVP).
Pages: Overview (historical versus prospective distinctly labeled), Upcoming (fixture timestamp, model/version, stale/blocked/no prediction states), Tournaments (edition and surface), Results (immutable predictions and revised outcome history), Model Lab (reference and candidates, training status, no automatic promotion), Data Health (rights, last successful job, failures, quarantine and next action). Read-only historical evidence first. No fake upcoming records in normal mode; synthetic demonstration explicitly marked and isolated. Keyboard navigation, descriptive labels, no color-only meaning, readable tables, empty/error states. Rendered visual/accessibility QA required before UI acceptance; conceptual review is not visual QA.

## Contracts and gates
S1 historical read model + offline UI: exact P2.4 evidence hash, expected historical-only status, 18 model rows, 7694 matched observations, three year counts; validate and fail visibly on corruption. Accuracy from fixed bins with p(A)>=.5 choosing A (tie policy shown); LL/Brier/ECE, support and coverage; no live values invented. Pure reader has no network/database/training or Streamlit dependency. UI separate; localhost launch and AppTest/manual Windows visual check required. No model/source refit. S1 ends once evidence fidelity, empty/invalid states, tests and rendered QA pass.
S2 SQLite schema: source permission records, immutable snapshots, canonical players/aliases, editions, match identity, fixture/result revisions, feature snapshots, model versions, predictions/evaluations/job runs/quarantine. Unique provider IDs with explicit crosswalk, FK, migration transaction, duplicate retries no-op, backups/restoration tested. Timestamps UTC; distinguish event time, observed/available time, prediction cutoff, actual start and result publication. Never infer observed availability from a provider event date. Keep source revisions append-only. Stop on complete migration/restore tests.
S3 synthetic ingestion: typed provider adapter, explicit source rights gate checked before any fetch, allowlisted URLs, limits/retry/backoff and quarantine, no silent mapping. No real request until S8 permission receipt. Source rights must cover automated fetch, retention, model fitting/persistence, derived metrics, provider ID mapping, permitted limits and third-party restrictions. Stop after contract tests with fake provider and proven no network when locked.
S4 inference: separate label-free UpcomingFixture, matured HistoricalResult and FeatureSnapshot. V3 18 features and 28-day pre-event maturity preserved for initial parity; no same-event outcome. No fabricated placeholder labels. Parity on permitted pinned history (or synthetic tests if real locked); actual historical local refit or persistence needs separate scope. Strict point-in-time eligibility: both known availability and protocol cutoff, prestart receipt; changed participants invalidate old fixture binding. Versioned model/feature digest, deterministic test parity, no poststart forecast. Stop when synthetic inference/temporal tests pass; historical parity explicitly pending if no approved inputs.
S5 sequential evaluation: append-only prediction commit before result visibility; freeze fixture/model/feature and timestamp; score only confirmed eligible matches with verified prestart timing, result revision linked, corrections append new assessment, no deletion. Explicit void/walkover/retirement/missing/ties policy; no silent drops, denominators fixed, report coverage plus accuracy/LL/Brier/ECE, by version/time/tier/surface. Local commitments are not independently authenticated. Stop after end-to-end synthetic prospective simulation and revision/restart tests.
S6 controlled training: separate fit/calibration chronological windows, immutable cutoff/lineage/config/dependency hashes, isolated safe model storage, candidate registry and manual promotion; no auto replacement. Weekly eligibility check and 200 new eligible outcomes proposed operational threshold, not power. Freeze candidate before matched subsequent evaluation; consumed outcomes cannot serve as that model's untouched validation. No real fitting or model persistence without new rights/approval. Stop after synthetic training, reproducibility and rollback tests; production promotion not part of S6.
S7 local deployment: pinned dependencies with separate V4 environment, install/launch instructions, health/backup/recovery, worker off by default, regression CI and independent review, actual Windows smoke and rendered UX QA. Stop at usable offline release; synthetic vs historical labels and real data locked.
S8 separate activation: verify actual source terms and provider confirmation as needed, independent identity/fixture/result and timestamp coverage, signed owner authorization and data scope, isolation from any reserved holdout, approved temporal protocol, real parity and one bounded dry run, operational budget/limits. If rights or timing absent, remain offline. No actual source accessed in V4 design. Continuous research is sequential not a new untouched holdout.

## Anti-loop and completion
Each stage has one scoped deliverable, RED then GREEN plus regression suite, evidence and one independent review with targeted follow-up. At most two remediation attempts per material finding before disposition; no reopen accepted scope without concrete failing requirement. PASS only for tested scope, BLOCKED if prerequisites missing. S1-S7 offline release separate from S8 authorization. Main protected; no merge without exact-head owner approval. No UI visual audit claimed until capture of actual rendered app. Product design standard chat workflow unavailable; implementation here begins with non-UI S1 contract only. No speculative feature expansion.
