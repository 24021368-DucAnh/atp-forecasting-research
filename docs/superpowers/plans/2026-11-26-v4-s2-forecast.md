## Interfaces and data constraints
Files: schema_v3.py, forecast.py, narrow identity.py version compatibility,
tests/v4/test_database_forecast.py.
Frozen records, positional field order:
FeatureSnapshot(feature_id,fixture_id,feature_digest,cutoff)
ModelVersion(model_id,model_digest,config_digest,training_cutoff,created_at,scope)
Prediction(prediction_id,match_id,fixture_id,feature_id,model_id,created_at,probability_a,commitment_digest)
Evaluation(evaluation_id,prediction_id,result_id,evaluated_at,status)
JobRun(job_id,kind,attempt,started_at,ended_at,status)
QualityIssue(issue_id,source_id,observed_at,reason)
migrate_forecast(conn)->3 from recognized v2 or v3 only.
append_feature, append_model, append_prediction, append_evaluation,
record_job, record_quality_issue(conn, typed record)->bool; require caller
transaction, FK+recursive triggers, exact v3; identical canonical replay False,
conflicting replay ValueError. IDs SYN- with existing identity pattern;
digest 64 lowercase hex. All known timestamps normalize with existing
utc_timestamp; no naive/invalid time. Model scope SYNTHETIC; created_at >=
training_cutoff. Prediction probability finite real number 0..1, reject
bool, string, NaN and infinity; DB NOT NULL and CHECK. Fixture FK, match
binding, exact feature/fixture binding, model FK, UNIQUE(fixture_id,model_id).
Evaluation FK plus result belongs to same match as prediction;
UNIQUE(prediction_id,result_id), RECORDED/VOID/INELIGIBLE status only,
evaluated_at >= prediction creation and result observation. No scores,
settlement policy or temporal eligibility certification (S4/S5).
Job kind INGEST/FEATURES/PREDICT/EVALUATE/TRAIN/BACKUP; immutable completed
attempt receipt, positive attempt, ended >= started, terminal
SUCCEEDED/FAILED/BLOCKED; no RUNNING job lifecycle or scheduler yet.
Quality issue source FK, nonempty reason; caller must avoid secrets.
All six tables forbid update/delete/replacement via writer triggers.
Local commitment_digest stores caller-provided syntactically valid hash,
not an authenticated prestart receipt; actual computation/eligibility S5.
Read list_prediction_history(conn,match_id)->list[dict], order by created_at
then prediction_id, exact stored fields and evaluations list sorted by
evaluated_at/evaluation_id. Works on read-only connection, no writes.
No claim a stored synthetic prediction is a validated forecast.
