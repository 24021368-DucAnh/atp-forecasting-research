# S2.2 - Immutable identity and revisions implementation plan

> For agentic workers: use superpowers:executing-plans and test-driven-development.

Goal: add durable, synthetic-only source, player, tournament, match, fixture
and result records to the existing bootstrap. Spec: original V4 design
and issue #61. Base c6003be426fd530bc043d47b5899572b7906d908; PR #62 merged at exact GREEN tree.
No live source, DB UI, training, model artifact or worker. No new dependency.
Schema version 2 is a separate migration from exact version 1, not a
reinterpretation of the merged bootstrap. Keep migrate() bootstrap contract
unchanged; migrate_identity(conn) requires a recognized v1 or v2 and rejects
damaged schemas. v2 is not the final S2 schema. Task 3 extends explicitly.

## Files and interfaces
Create src/atp_lab/database/schema_v2.py (trusted DDL, exact schema objects),
identity.py (frozen dataclass records and inserts); extend connection.py
to enable recursive_triggers=ON for writer, preserving old contracts.
Migration must verify v1 marker/schema inside BEGIN IMMEDIATE and verify v2
schema/marker on reopen (including triggers); reject unknown/forged version.
Existing bootstrap tests unchanged. Use trusted SQL only.
Identity module exports migrate_identity(conn)->int, Source(source_id,mode,
permission_status), Snapshot(snapshot_id,source_id,digest,observed_at),
Player(player_id), PlayerAlias(source_id,provider_player_id,player_id),
Tournament(tournament_id,event_key,edition,tier,surface),
Match(match_id,tournament_id,canonical_a,canonical_b),
MatchAlias(source_id,provider_match_id,match_id),
Fixture(fixture_id,match_id,revision,source_id,snapshot_id,player_a,player_b,
observed_at,available_at,scheduled_start,state),
Result(result_id,match_id,revision,source_id,snapshot_id,observed_at,
available_at,published_at,actual_start,state,winner).
Fields are strings except positive revision integer; timestamp optional
fields and winner are str or None. All source and internal IDs synthetic
namespace SYN- with nonempty suffix. Provider aliases nonempty strings.
Source fixed SYNTHETIC/LOCKED, digest 64 lowercase hex. Tournament unique
(event_key,edition); surface HARD/CLAY/GRASS/UNKNOWN; tier ATP250/ATP500/
MASTERS1000/GRAND_SLAM/FINALS/OTHER. Match players distinct and sorted;
same pair not a unique match key (can play twice). Player and match
aliases unique within source, explicit crosswalk; no fuzzy merge.
Fixture states SCHEDULED/POSTPONED/CANCELLED/UNKNOWN; result states
COMPLETED/RETIRED/WALKOVER/VOID/UNKNOWN; winner required for COMPLETED,
optional for retirement/walkover, absent for VOID/UNKNOWN, always belongs
to match if present. Scheduled start may be unknown except SCHEDULED.
Snapshot observed_at <= revision observed_at. Available_at means known
local eligibility and must be >= observation when present; unknown stays
NULL. Publication/actual start when present <= observation; when both
known start <= publication. No temporal prediction guarantees yet.
Use timezone-aware RFC3339 with offsets and normalize to fixed microseconds
UTC Z; reject naive/invalid dates, don't infer unavailable times.
Fixture and result revisions unique (match_id,source_id,revision);
retain explicit source, snapshot and exact binding. Participant changes
cannot overwrite a canonical match or alias: conflict requires explicit
resolution in S3/S4. Allow version correction as separate immutable row.
Implement foreign keys including composite source/snapshot and match/pair
and DB checks/triggers for membership. Immutable records block UPDATE/
DELETE and replacement via recursive triggers; trusted writer only, not
tamper-proof against arbitrary administrator SQL. put_source, put_snapshot,
put_player, put_alias, put_tournament, put_match, put_match_alias,
append_fixture, append_result: (conn, typed record)->bool, caller must
hold explicit transaction with FK and recursive triggers active; identical
canonical field replay False, differing same key ValueError; conflicts
with other constraints reject; no implicit commit or overwrite.
Explicitly added match_aliases crosswalk because provider match IDs cannot
be assumed globally stable. One extra relation, within identity scope.
