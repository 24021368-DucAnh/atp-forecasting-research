Base S3.1 verified GREEN d8efd4c1c61f3a4207dfa25715b3b5a9e3c1c4d7; continue PR #66, issue #65.
No network, real ingestion, database writes in parser, new DDL, model or UI.
Files: ingestion/parser.py, tests/v4/test_ingestion_parser.py.

Interface parse_batch(conn, receipt: FetchedPayload, *, observed_at: str,
available_at: str | None) -> ParsedBatch(snapshot: identity.Snapshot,
fixtures: tuple[identity.Fixture,...], results: tuple[identity.Result,...]).
Frozen typed return. Caller supplies local clocks, never accept these from
provider JSON. Normalize existing utc_timestamp, known availability >=
observation, unknown availability NULL. Read-only DB or caller transaction;
requires verified S2 v3 schema by caller, parser checks version and source
record mode SYNTHETIC / permission LOCKED. No side effects, no new aliases.
Revalidate receipt exact type, synthetic source syntax, fixed endpoint,
attempt count 1..3, exact bytes nonempty <=1 MiB, digest matches SHA256.
Receipt is not an authorization token; only S3.3 orchestrator invokes
rights gate before fetching, parser does not fetch or certify origin.

Strict UTF-8 JSON, duplicate key rejection at every object, reject nonfinite
JSON constants, malformed/deep recursion, require exact top-level object
with one matching endpoint key fixtures or results, list <=1000 rows.
Empty list is valid. Each row exact fields (fixture: match_id, player_1,
player_2, revision, scheduled_start, state; result: match_id, player_1,
player_2, revision, published_at, actual_start, state, winner).
Provider IDs exact nonempty strings <=256 chars, no NUL or surrounding
whitespace, no fuzzy/automatic canonical mapping. Revision positive
exact int <= SQLite signed int max. Resolve match_aliases and both
player_aliases within receipt source; canonical sorted pair must match
stored match and be distinct; winner alias must map to participant.
No remap on changed participants. Reject duplicate canonical
(match_id,revision) within batch, even if provider aliases differ.
Use S2 states and timestamp constraints; required keys may be NULL only
where S2 allows. Result observed/published/actual clocks constraints
as S2; scheduled_start required for SCHEDULED. Never infer times.
All malformed input or unknown identity raises sanitized ParseError
(ValueError subclass) without echoing payload. Operational DB errors
propagate, not conflated with data quality. Bound JSON input by bytes and
row count; no adversarial sandbox.
Snapshot ID SYN-snapshot- plus SHA256 of canonical JSON array
[source_id,endpoint,digest,normalized observed_at]. Revision IDs
SYN-fixture- / SYN-result- plus SHA256 of canonical JSON array
[source_id,canonical match_id,revision]. Use json.dumps compact,
ensure_ascii=True and UTF-8, unambiguous fields. Snapshot digest exact
input bytes; same canonical observation and payload replay deterministic.
Different local observation gets distinct snapshot, stable revision ID.
S3.3 must define re-observation vs conflicting revision explicitly:
retain first immutable lineage, do not overwrite; same revision with
identical semantic provider fields may be no-op only under explicit
tested rules; no silent conflicting revision. Parser does not persist.
