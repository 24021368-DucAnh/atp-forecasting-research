Files prediction/__init__.py, prediction/temporal.py,

Frozen records in exact positional order:
UpcomingFixture(fixture_id,match_id,source_id,revision,tournament_id,
event_start:date,surface,player_a,player_b,observed_at,available_at,
scheduled_start,state).
HistoricalResult(result_id,match_id,source_id,revision,tournament_id,
event_start:date,surface,player_a,player_b,observed_at,available_at,
published_at,actual_start,state,winner).
No outcome/winner/label on target. All canonical IDs SYN- pattern;
positive exact int revision <= SQLite max; canonical player_a < player_b;
surface HARD/CLAY/GRASS only. Exact date (not datetime or string).
Event-start date is explicit synthetic UTC calendar metadata, never
inferred from scheduled or actual match time. S2 lacks event-start
column; later S4.3 requires explicit versioned metadata input.
Use identity.utc_timestamp for normalized UTC clocks, no guessed
availability. Fixture SCHEDULED only, scheduled start known and >=
event-start UTC date, observed <= available <= cutoff < scheduled start.
Invalid target or cutoff -> TemporalError(ValueError).
Historical states COMPLETED/RETIRED/WALKOVER/VOID/UNKNOWN;
winner belongs to pair, required COMPLETED, forbidden VOID/UNKNOWN.
Known availability >= observation; publication and actual start <=
observation; actual <= publication if both known; known actual date >=
event-start. Unknown nullable clocks remain None.
Reject malformed records (including future records; no claim untrusted
future input cannot cause an error); use only structurally valid inputs.

select_history(fixture, results: tuple/list, *, cutoff) -> tuple
of normalized HistoricalResult. Empty allowed. For visible observations
(observed_at <= cutoff), reject duplicate result ID or same
(source,match,revision), conflicting event/surface/pair identity within
a match, or multiple sources for same match (no silent reconciliation).
Select highest revision among observed per match; if latest has unknown
or after-cutoff availability, exclude rather than stale fallback.
Exclude target match and tournament; select only COMPLETED with known
actual start, publication and availability <= cutoff. Require event-start
+ 28 calendar days <= min(target event-start, UTC cutoff date), equivalent
to date difference >=28; no use of future event-day maturity. No
retired/walkover results in initial eligible feature history. Canonical
order (event_start,tournament_id,match_id,result_id), stable across input
order. Visible corrections replace prior result; future valid corrections
do not influence selected history. Within-event metadata across distinct
matches checked for consistency later in feature engineering. Synthetic
timestamps are claims, not independent proof of prestart eligibility.
No source fallback, no cross-source adjudication, no S2 schema change.
